YENGLISH EXAMS
PROJECT HANDOVER AND DEVELOPMENT SPECIFICATION
Version: MVP v1.0

PURPOSE
-------
This document is a complete handover specification for another AI developer. It explains the project, architecture, current implementation, operational workflow, security model, development principles, and future roadmap.

1. PROJECT OVERVIEW
------------------
YEnglish Exams is a Telegram-based English examination system for private English classes. Students do not need a separate application.

Core flow:

Teacher
  -> AI-generated questions
  -> Question Bank
  -> Exam Creation
  -> Exam Assignment
  -> Telegram Class Group
  -> Student
  -> Telegram Mini App
  -> Flask API
  -> SQLite database
  -> Server-side grading
  -> Result storage
  -> Private teacher Telegram notification

The current MVP has been tested end-to-end in Telegram.

2. MAIN GOAL
------------
The system should allow a teacher to:

- Maintain a reusable question bank.
- Import batches of AI-generated four-option MCQs.
- Create exams from existing questions.
- Assign exams to Telegram groups.
- Send exams to Telegram groups.
- Let students open exams inside Telegram.
- Authenticate students automatically through Telegram.
- Grade exams automatically on the server.
- Store results.
- Receive each student's result privately in Telegram.

Students should be able to:

- Open an assigned exam.
- See their name.
- Answer one question at a time.
- Move backward and forward.
- See progress.
- See a countdown timer.
- Submit the exam.
- Immediately see their result.

4. ARCHITECTURE
---------------
A single Flask server provides both the Mini App and API.

Telegram
   |
   v
ngrok HTTPS
   |
   v
Flask :5000
   |----------------------|
   v                      v
Mini App                 API
/                       /api/...
                           |
                           v
                        exam.db

This replaced an earlier architecture that used a separate Mini App server on port 8000 and API server on port 5000. The single-server architecture is simpler and avoids unnecessary CORS complexity.

6. FILES AND RESPONSIBILITIES
-----------------------------

database.py
Purpose:
Creates and initializes the SQLite schema.

Important:
The database file is exam.db. Do not accidentally switch to journal.db.

api.py
Purpose:
Central Flask application.

Responsibilities:
- Serve Mini App at /
- Health check at /api
- Validate Telegram Mini App initData
- Identify the registered student
- Check group-based exam access
- Return exam questions without correct answers
- Receive submitted answers
- Grade on the server
- Save results
- Notify the teacher privately through Telegram

Important endpoints:

GET /
Serves mini_app/index.html

GET /api
Backend health check.

GET /api/me
Authenticates Telegram initData from the HTTP header:
X-Telegram-Init-Data

GET /api/exam/<exam_id>
Returns basic exam information after authentication and access checking.

GET /api/exam/<exam_id>/questions
Returns exam title, time limit, question order, question text, and A/B/C/D options.
It must NOT return correct_answer.

POST /api/exam/submit
Receives:
- exam_id
- answers
- started_at

The server:
1. Authenticates Telegram.
2. Finds the registered student.
3. Checks group access.
4. Loads official answers from SQLite.
5. Calculates the score.
6. Saves the result.
7. Commits the database transaction.
8. Sends a private Telegram message to the teacher.
9. Returns the result to the student.

mini_app/index.html
Purpose:
Student-facing Telegram Mini App.

Responsibilities:
- Initialize Telegram WebApp
- Read Telegram initData
- Read the exam start parameter
- Authenticate through /api/me
- Load the exam
- Display one question at a time
- Display four options
- Remember selected answers locally
- Previous/Next navigation
- Progress bar
- Countdown timer
- Submit answers
- Display returned result

The frontend must never calculate authoritative correctness and must never contain the answer key.

mini_app/style.css
Purpose:
Dark, professional, mobile-first exam UI.

Features:
- Dark theme
- Responsive layout
- Large touch-friendly option buttons
- Selected-answer state
- Progress bar
- Timer
- Result display
- Suitable for Telegram mobile screens

question_parser.py
Purpose:
Parses AI-generated question batches.

Supported format:

id="abc123"

[QUESTION]
She _____ to school every day.
[A] go
[B] goes
[C] going
[D] gone
[ANSWER] B

It extracts question text, options A-D, and the correct answer.

import_questions.py
Purpose:
Imports parsed questions into the question bank.

add_question.py
Purpose:
Manual question insertion utility used during development.

create_exam.py
Purpose:
Creates exams and attaches selected questions in a chosen order.

assign_exam.py
Purpose:
Assigns an exam to a group.

add_group.py
Purpose:
Registers Telegram groups/classes.

add_student.py
Purpose:
Registers Telegram students and associates them with a group.

send_exam.py
Purpose:
Sends an exam announcement to a Telegram group with a Start Exam button.

test_submit.py
Purpose:
Development-only submission API testing.

button_test_bot.py
Purpose:
Development-only test for Telegram button callbacks.

7. TELEGRAM WORKFLOW
--------------------
Teacher creates an exam.
Teacher assigns the exam to a group.
Teacher sends the exam announcement.
Student taps Start Exam.
Telegram opens the Mini App.
Telegram supplies initData.
Mini App sends initData to Flask.
Flask verifies the Telegram signature.
Flask identifies the student.
Flask checks whether the student's group has access.
Flask returns questions without answer keys.
Student completes the exam.
Mini App submits answers.
Flask grades the answers.
Flask stores the result.
Flask sends the teacher a private result message.
Student sees the result.

8. SECURITY MODEL
-----------------
The following rules are fundamental.

1. Never trust student_id from browser input.
The server derives the student from validated Telegram initData.

2. Never send correct_answer to the Mini App.

3. Never perform authoritative grading in JavaScript.
The server must compare answers against SQLite.

4. Always check exam access on the server.
Knowing an exam_id must not automatically grant access.

5. Keep secrets outside source code.
At minimum:
TELEGRAM_BOT_TOKEN
TEACHER_TELEGRAM_ID

6. Never place the bot token in index.html or any client-side JavaScript.

7. Save and commit the result before attempting teacher notification.
A Telegram notification failure must not erase a valid exam result.

12. AI QUESTION GENERATION WORKFLOW
-----------------------------------
The teacher provides lesson material to an AI.

The AI generates four-option MCQs.

The teacher copies the generated batch.

question_parser.py converts the text into structured questions.

import_questions.py stores them in the question bank.

The question bank is then used to build exams.

Conceptual pipeline:

AI
 -> Question Parser
 -> Question Bank
 -> Exam Builder
 -> Telegram Group
 -> Student Mini App
 -> Flask
 -> Result

This separation should be preserved.

- authentication reliability
- exam access
- submission reliability
- timer behavior
- score accuracy
- database integrity
- teacher notifications
- network interruption

Fix real problems before adding major features.

Build a teacher panel inside Telegram.

- Dashboard
- Groups
- Students
- Question Bank
- Exams
- Assignments
- Results

The teacher should eventually perform all administrative tasks without running Python helper scripts.

PHASE 3 - QUESTION BANK UI
Add:
- Add question
- Edit question
- Delete question
- Search
- Select questions
- Import AI question batches

Keep the existing AI parser compatible.

PHASE 4 - EXAM BUILDER
Teacher should be able to:
- Create title
- Set time limit
- Select questions
- Arrange order
- Save exam
- Assign exam to groups
- Send exam

PHASE 5 - RESULTS
Teacher results page:
- Student
- Exam
- Score
- Percentage
- Date/time
- Completion time

Later:
- Per-question performance
- Student history
- Exam averages
- Class performance
- Question performance

PHASE 6 - SERVER-SIDE ATTEMPT TIMING
Currently the browser countdown is primarily a UI mechanism.

Future design:
Server records start time.
Server calculates elapsed time.
Server decides whether submission is within the allowed duration.

PHASE 7 - DUPLICATE SUBMISSION CONTROL
Define a formal attempt policy.

If one-attempt-only is desired, enforce it safely at the database/service level.

If multiple attempts are later required, introduce a dedicated attempts model rather than overloading results.

PHASE 8 - MORE QUESTION TYPES
Possible future types:
- True/False
- Matching
- Fill in the blank
- Ordering
- Vocabulary
- Listening
- Reading comprehension

Each new question type needs an explicit data model before implementation.

PHASE 9 - ANALYTICS
Possible analytics:
- Student performance
- Question performance
- Exam performance
- Class performance
- Historical improvement

Only add analytics after the underlying data model is stable.

17. ERROR HANDLING
-----------------
Student-facing errors should be simple:

"Telegram authentication failed."
"Your Telegram account is not registered as a student."
"You do not have access to this exam."
"Exam not found."
"Could not load the exam."
"Could not submit the exam."

Do not expose internal database errors or credentials.

18. RESULT DATA FLOW
--------------------
Example submitted answers:

{
    "1": "B",
    "3": "C",
    "4": "B"
}

The browser does not submit a score.

The server loads official answers from SQLite and calculates the score.

For three questions:
3 correct = 3/3
2 correct = 2/3
1 correct = 1/3
0 correct = 0/3

The result is stored in results and the teacher is notified privately.
