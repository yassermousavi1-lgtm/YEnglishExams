1. WHAT IS THIS PROJECT?
================================================================================

YEnglish Exams is a Telegram-based English examination system for private
English classes. Students do NOT need a separate application. Everything
runs inside Telegram as a Mini App.

The teacher uses it to:
  - Create exam questions (MCQ and Word Bank Gap-Fill).
  - Assign exams to Telegram groups.
  - Send exams to groups with a Start Exam button.
  - View results and analytics.
  - Manage students, attendance, and weekly class schedules.

Students use it to:
  - Open an exam inside Telegram.
  - Authenticate automatically through Telegram.
  - Answer questions (MCQ click or Word Bank drag-and-drop).
  - Submit the exam.
  - See their result immediately.

Core flow:

  Teacher
    -> Create Exam (MCQ or Word Bank)
    -> Assign to Telegram Group
    -> Send Exam to Group
    -> Student taps Start Exam
    -> Telegram Mini App opens
    -> Flask API authenticates via Telegram initData
    -> SQLite database returns questions (without answers)
    -> Student answers
    -> Flask grades on server
    -> Result stored in SQLite
    -> Teacher receives private Telegram notification
    -> Student sees result

2. WHAT DOES IT DO? (FEATURES)
================================================================================

TEACHER FEATURES (inside Mini App):
  - Dashboard with all management sections.
  - Add / delete students.
  - Add groups (Telegram class groups).
  - Create MCQ exams (4-option multiple choice).
  - Create Word Bank Gap-Fill exams (drag-and-drop vocabulary).
  - Send exams to groups with a deep-link Start Exam button.
  - Preview exams before sending (with Finish Preview button).
  - View all results (active and archived).
  - Archive / unarchive results.
  - Share result details via Telegram.
  - Student profile with archived results and attendance.
  - Record attendance sessions per student.
  - Mark sessions as Make-up or Regular.
  - Add extra minutes to attendance sessions.
  - Weekly class schedule (Today + Full Week view).
  - Add / edit / delete schedule sessions per student.
  - Share a student's full schedule via Telegram.

STUDENT FEATURES (inside Mini App):
  - Telegram auto-authentication.
  - Opens only assigned exams.
  - MCQ: one question at a time, four options.
  - Word Bank: drag words from word bank into sentence blanks.
  - Countdown timer with red warning in last 60 seconds.
  - Automatic submit when time runs out.
  - Result displayed immediately after submit.

SUPPORTED QUESTION TYPES:
  1. MCQ (Multiple Choice - 4 options)
  2. Word Bank Gap-Fill (drag-and-drop, any number of sentences)
     - Word bank has exactly ONE extra word (distractor).
     - word_bank.length must equal questions.length + 1.
     - Supports any number of sentences (5, 8, 10, 20, etc.)
     - Student drags words into blanks; clicking a filled blank returns
       the word to the bank.

5. DATABASE SCHEMA (exam.db)
================================================================================

All tables use SQLite with foreign keys enabled.

--------------------------------------------------------------------------------
TABLE: groups
  Stores Telegram groups (classes) for exam assignment.
  Columns: id, telegram_group_id (unique), name, created_at
--------------------------------------------------------------------------------
TABLE: students
  Each student belongs to exactly one group.
  Columns: id, telegram_user_id (unique), first_name, last_name,
           username, group_id (FK -> groups), color, created_at
  color: automatic palette color for schedule visualization.
--------------------------------------------------------------------------------
TABLE: questions
  MCQ question bank.
  Columns: id, question_text, option_a, option_b, option_c, option_d,
           correct_answer (A/B/C/D), created_at
  NOTE: This table is for MCQ only. Word Bank uses a separate table.
--------------------------------------------------------------------------------
TABLE: exams
  Exam metadata.
  Columns: id, title, time_limit, category, exam_type, created_at
  exam_type: 'mcq' (default) OR 'word_bank'.
             Determines how questions are loaded and graded.
--------------------------------------------------------------------------------
TABLE: exam_questions
  Links MCQ questions to exams (many-to-many with order).
  Columns: id, exam_id (FK), question_id (FK), question_order
  UNIQUE(exam_id, question_id)
--------------------------------------------------------------------------------
TABLE: results
  One row per completed exam attempt (both MCQ and Word Bank).
  Columns: id, student_id (FK), exam_id (FK), score, total_questions,
           started_at, completed_at, is_archived, exam_title_snapshot
  exam_title_snapshot: preserves title even if exam is deleted.
--------------------------------------------------------------------------------
TABLE: student_answers
  Per-question answers for MCQ exams only.
  Columns: id, result_id (FK), question_id (FK), selected_answer,
           is_correct
  NOTE: Word Bank does NOT use this table. It uses word_bank_answers.
--------------------------------------------------------------------------------
TABLE: exam_assignments
  Links exams to groups.
  Columns: id, exam_id (FK), group_id (FK), assigned_at
  UNIQUE(exam_id, group_id)
--------------------------------------------------------------------------------
TABLE: attendance
  Attendance sessions per student.
  Columns: id, student_id (FK), session_number, extra_minutes,
           is_makeup, created_at
--------------------------------------------------------------------------------
TABLE: class_schedule
  Weekly private class sessions (one row per session).
  Columns: id, student_id (FK), day_of_week, start_time, end_time,
           notes, created_at
  NOTE: Uses student_id (NOT class_group_id). class_groups table was
        removed in a previous migration.
--------------------------------------------------------------------------------
TABLE: word_bank_questions
  One row = one complete Word Bank set (any number of sentences).
  Columns: id, exam_id (FK), question_order,
           student_data_json, answer_key_json, created_at

  student_data_json:
    JSON sent to the student (NO answers).
    Sentences have the answer word replaced with "_____".
    Format:
      {
        "instruction": "...",
        "word_bank": ["...", ...],
        "questions": [
          { "number": 1, "sentence": "Regular exercise can _____ your health." },
          ...
        ]
      }

  answer_key_json:
    Server-only. Contains answers and extra_word.
    Format:
      {
        "answers": [
          { "number": 1, "answer": "improve" },
          ...
        ],
        "extra_word": "ancient"
      }
--------------------------------------------------------------------------------
TABLE: word_bank_answers
  One row per completed Word Bank attempt.
  Columns: id, result_id (FK), exam_id (FK),
           selected_answers_json, details_json,
           correct_count, total_count

  selected_answers_json: { questionId: { sentenceNumber: word } }
  details_json: list of per-sentence results (for result details view).
--------------------------------------------------------------------------------

MIGRATIONS (handled automatically in both database.py and api.py):
  - exams.category
  - results.is_archived
  - results.exam_title_snapshot
  - students.color
  - attendance table
  - class_schedule rebuilt with student_id
  - class_groups dropped
  - exams.exam_type (default 'mcq')
  - word_bank_questions table
  - word_bank_answers table

All migrations are additive and SAFE. No existing data is ever dropped
without explicit request.

6. TEACHER WORKFLOW (inside Mini App)
================================================================================

1. Teacher opens Mini App in Telegram.
2. Flask authenticates via Telegram initData.
3. If teacher: Dashboard is shown with all sections:
   - Create (Add Student, Add Group, Create Exam, Send Exam)
   - Management (Students, Exams, Results)
   - Schedule (My Schedule)

CREATE EXAM:
  - Teacher taps "Create Exam".
  - Chooses type: MCQ (4 Options) or Word Bank.
  - For MCQ: paste an array of MCQ JSON.
  - For Word Bank: paste a single object with:
      instruction, word_bank, questions, extra_word
  - Backend validates Word Bank (flexible: word_bank = questions + 1).
  - Exam is stored with exam_type = 'mcq' or 'word_bank'.

PREVIEW:
  - Teacher taps the 👁 button next to any exam.
  - MCQ: full preview with Previous/Next and Finish Preview.
  - Word Bank: full drag-and-drop preview with Finish Preview.
  - Preview does NOT save results.

SEND EXAM:
  - Teacher taps "Send Exam".
  - Searches / filters exams.
  - Assigns to one or more groups.
  - Sends the exam announcement to the group with a Start Exam button.
  - Deep link format: https://t.me/YEnglsihExamsbot?startapp=exam_<ID>

================================================================================
7. STUDENT WORKFLOW (inside Mini App)
================================================================================

1. Student taps the Start Exam button in the Telegram group.
2. Telegram opens the Mini App with start_param = "exam_<ID>".
3. Flask authenticates via Telegram initData.
4. Flask finds the registered student by telegram_user_id.
5. Flask checks that the exam is assigned to the student's group.
6. Flask checks that the student has not already taken this exam.
7. Flask returns questions (WITHOUT answers).
8. Student answers.
9. Timer runs in the browser; last 60 seconds shows red warning.
10. When time runs out: auto-submit with whatever answers exist.
11. Flask grades on the server.
12. Result is stored in the database.
13. Teacher receives a private Telegram notification.
14. Student sees the result immediately.

8. SECURITY MODEL (MUST BE PRESERVED)
================================================================================

1. Never trust student_id from browser input.
   The server ALWAYS derives the student from validated Telegram initData.

2. Never send correct_answer to the Mini App for MCQ.

3. Never send "answer" or "extra_word" to the Mini App for Word Bank.
   The server strips them before sending (build_word_bank_student_data).

4. Never grade on the client. All grading is server-side.

5. Always check exam access on the server (group-based).

6. Keep secrets outside source code:
   TELEGRAM_BOT_TOKEN and TEACHER_TELEGRAM_ID are set as environment
   variables in the WSGI file on PythonAnywhere, and must NEVER be
   placed in index.html, JavaScript, or any client-side file.

7. Save and commit the result BEFORE attempting teacher notification.
   A Telegram notification failure must not erase a valid result.
